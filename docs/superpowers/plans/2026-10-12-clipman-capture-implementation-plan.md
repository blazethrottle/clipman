# Chrome 발췌 흐름 구현 계획

기준: 2026-10-12 승인 설계와 HANDOFF. 9월 계획의 M1 구현은 유지하고 M2 이후는 아래 순서로 진행함.

## 이번 착수 단위: 구간과 작업 관리 기반

1. 기존 107개 단위 테스트를 실행함.
2. Windows 번들 실행파일을 조달하고 버전, 출처, 해시를 기록함. 기존 실제 인코딩 검사 5개를 실행함.
3. 아키텍처에 Chrome 연결과 시각 계약을 먼저 기록함.
4. 선택 영상 URL과 원본 시작/끝, 확보 파일의 원본 기준 시각을 분리한 자료형을 구현함. NaN, 무한대, 역전, 영상 식별 불일치와 확보 범위 밖 편집을 거부함.
5. 기존 다운로드 명령에 선택 구간 옵션을 추가함. 전체 다운로드 호출과 쿠키 폴백 호환을 유지함.
6. M2 작업 관리자를 구현함. 상태 전이, 진행률, 실제 프로세스 종료, 원본과 완성 출력 보존, 재편집, 취소 뒤 늦은 완료의 무효화를 검사함.

완료 조건: 기본 스위트 통과, 실제 인코딩 검사 통과, 신규 실패 조건의 회귀 검사 통과와 변경 검토. Chrome 연결이나 실제 YouTube 획득이 구현됐다고 표시하지 않음.

## 후속 순서

| 단계 | 산출물 | 완료 조건 |
|---|---|---|
| M3 구간 확보와 편집 서비스 | Popen 실행, 다운로드 결과 탐색, ffprobe, 원본 매핑, 임시 인코딩 후 원자적 출력 이동 | 실제 구간 길이/장면/음성 검사, 실패와 취소, 원본 재사용 |
| M4 로컬 HTTP 연결 | 엄격한 Host/Origin와 토큰 검사, 구간 요청/상태/원본/출력/취소 API | 웹사이트 요청 거부, 경로 제한, Range 재생, 중복 작업 방어 |
| M5 Chrome 확장과 핵심 UI | 재생 시각 표시, 사이드 패널, Svelte/Vite 편집 탭, 작업 복원 | 영상 이동 시 마커 초기화, 화면 크기별 크롭 일치, 진행과 취소 |
| M6 설치와 종단 검증 | Mac/Windows 실행기, 최초 연결 안내, 실제 Chrome 테스트 | 시청 중 표시부터 MP4 저장과 재편집까지 완주 |
| 획득 방식 비교 | 선택 구간 다운로드 대 탭 녹화 실측 | 장면, 음성, 대기와 전송량을 같은 영상으로 비교 |
| 모바일 계획 | iOS/Android 진입, 획득과 인코딩 설계 | 기기에서 편집과 저장까지의 가능성을 먼저 실증 |

## 구현 판정 기록

- localhost HTTP를 첫 연결로 선택함. 기존 FastAPI 및 Range 재생을 활용하고 Native Messaging 등록을 초기 설치에 추가하지 않기 위함. loopback 바인딩만으로 안전하다고 판단하지 않으며 M4의 Host/Origin/토큰 검사를 필수 관문으로 둠.
- 포트는 9000을 우선 사용하고 점유 시 실행기가 실제 포트와 연결 토큰을 안내함. 확장은 이를 최초 1회 연결 설정에 저장함. 자동 포트 탐색으로 임의 서버를 신뢰하지 않음.
- Chrome MV3 content script는 영상 ID와 시각만 읽음. 서비스 워커가 로컬 요청을 중계하고 편집 탭이 구간 원본을 재생함. Svelte/Vite는 편집 UI에 유지함.
- 이번 단위는 연결 전의 기반 구현임. UI 시안, API, 실제 YouTube 획득과 macOS 검증은 완료 범위에 포함하지 않음.
