# Chrome 첫 연결 구현 단위

기존 구간 기반 커밋 `f97bdc3` 다음 작업임. 승인된 Chrome 확장 + 로컬 프로그램 구조를 구현하며 M3~M5를 하나의 개발 연결로 검증함.

## 결정과 화면

- localhost와 MV3 서비스 워커 연결을 유지함. 소스와 출력은 작업별 서명된 읽기 URL로 재생하며 변경 요청은 헤더 연결 키를 사용함. Host 정확 비교, 임의 웹 Origin 거부 및 고정 확장 ID 검사를 적용함. 미들웨어는 오류 응답을 직접 반환함.
- content script에는 로컬 연결 키를 전달하지 않음. YouTube의 현재 ID/재생 시각을 읽는 메시지와 구간 재생만 지원함. 서비스 워커의 로컬 API 호출은 확장 자체 페이지에서만 허용함. 임의 URL fetch 중계는 제공하지 않음.
- 서버 실행기가 기존 Python 환경과 번들 도구를 확인하고 포트를 잡은 소켓 자체로 서버를 실행함. 연결 안내 페이지에서 사용자가 확장에 붙여 넣을 코드를 복사함. 연결 코드는 gitignore 경로에만 둠.
- 화면: 밝은 회색 `#F3F5F7`, 흰색 `#FFFFFF`, 본문 `#18232F`, 파랑 `#356AE6`, 구분선 `#DDE3EA`, 영상 배경 `#151B25`. 시스템 한국어 고딕을 사용함. 패널에는 선택과 상태를 세로로 배치하고 편집 탭에는 큰 영상 무대와 구간/구도 조절을 배치함. 영상의 9:16 틀이 시각적 중심이며 대시보드 카드와 통계를 추가하지 않음.
- 미리보기는 원본 픽셀 기준 9:16 crop 폭과 짝수 x를 사용함. PAD는 단색 여백으로 표현함. 입력/확보 시각은 명시적으로 구분함.

## 구현과 관문

1. 실행/등록/취소와 출력 게시를 같은 작업 잠금으로 직렬화함. Windows 프로세스 트리는 taskkill, POSIX는 별도 세션의 프로세스 그룹을 종료함. 실제 소유한 PID/그룹만 사용함.
2. 구간 확보, probe, 편집 및 검증 후 고유 이름으로 원자적 출력 게시함. 출력 길이/해상도/음성을 검증함. 확보 파일 0초는 요청한 정밀 컷 시작의 매핑으로 기록하며 실제 YouTube 장면으로 origin을 검증했다고 표시하지 않음.
3. HTTP 연결 키/출처/Host/요청 스키마, 상태 및 취소, Range 소스/출력 재생을 검사함. 경로는 서버가 보유한 job 자료로만 결정함.
4. MV3 패널, content script, 서비스 워커, Svelte 편집 탭과 연결 안내를 구현함. 영상 이동 시 구간 초기화, 새로고침 시 job 재조회, 안전한 메시지 경계를 검사함.
5. 실제 합성 파일과 API로 확보 -> 편집 -> 출력 및 재편집/취소를 검사함. 브라우저 UI를 실제 Chromium에서 확인함.

Chrome Web Store 게시, 일반 사용자 패키징, macOS와 모바일 실기기, 실제 YouTube 접근 및 탭 녹화 비교는 별도 관문임. 이번 개발 검사와 제품 종단 승인을 구분함.
