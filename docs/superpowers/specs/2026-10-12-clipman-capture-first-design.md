# clipman 발췌 중심 제품 설계

- 작성 및 사용자 승인: 2026-10-12, 서울 기준
- 승인 근거: 사용자가 제품 목적과 사용 환경을 정정하고 초기 Chrome 확장 + 로컬 처리 프로그램 추천에 승인한 뒤 GitHub 핸드오프 기록을 요청함
- 정본 범위: 제품 의도, 초기 형태, 주요 사용자 흐름, 플랫폼 목표와 범위
- 상세 연결 계약과 API 및 구현 순서: 다음 개발 세션이 이 설계를 입력으로 갱신할 대상

## 1. 목적과 사용자 환경

YouTube에서 마음에 드는 영상의 특정 부분을 발췌하고 인용해 쇼츠로 재편집함. 핵심 사용 순간은 YouTube를 보다가 마음에 든 장면을 발견했을 때임. 팬덤, 특정 언어, 장르나 자동 바이럴 추천에 제품을 한정하지 않음.

현재 사용자 환경은 데스크톱 Chrome과 모바일 iOS YouTube 앱임. Android도 지원 대상으로 고려함. 모바일 목표는 발췌, 편집과 저장까지 기기에서 완료하는 것이며 PC에 URL을 보내는 기능만으로 축소하지 않음.

## 2. 승인된 초기 형태

초기 제품은 데스크톱 **Chrome 확장 + 로컬 영상 처리 프로그램**임. 확장은 시청 중 구간 표시와 UI를 맡고 로컬 프로그램은 구간 확보 및 영상 처리를 맡음. 확장 외에 로컬 프로그램의 최초 설치가 필요함을 명확히 안내함.

기존 Python + FastAPI와 번들 yt-dlp, ffmpeg, ffprobe를 로컬 엔진의 출발점으로 사용함. macOS 우선 및 Windows 호환이라는 기존 엔진 결정을 유지함. 승인되지 않은 클라우드 영상 처리나 사용자 계정을 추가하지 않음.

## 3. 핵심 경험

1. **시청 중 구간 표시:** Chrome의 YouTube 재생 화면에서 시작과 끝을 정함. 이미 지나간 구간도 마커를 조정해 선택할 수 있어야 함.
2. **선택 확인:** 시작, 끝과 길이를 확인하고 구간을 다시 재생함. 다른 영상으로 이동한 뒤 잘못된 URL과 시각을 조합하지 않아야 함.
3. **확보 및 세로 구도:** 선택 구간을 확보하고 중앙 크롭, 위치 조절 크롭 또는 단색 여백으로 9:16 결과를 확인함. 전체 다운로드 대기를 필수 선행 단계로 두지 않음.
4. **저장:** 쇼츠 만들기를 누르면 처리 상태와 취소를 제공하고 완료한 MP4를 저장함. 확보한 원본을 사용해 재편집 가능함.

공통 모델은 소스 식별자 및 URL, YouTube 원본 시작/끝, 확보 파일의 원본 시각 기준, 편집 트림과 크롭 설정임. 잘라 받은 파일의 0초를 YouTube 0초로 오해하지 않도록 자료형과 테스트를 정함.

## 4. 영상 확보 정책

전체 다운로드, 선택 구간 가져오기와 부분 녹화는 구간을 얻는 수단임. 기본 검증 후보는 yt-dlp의 선택 구간 가져오기이며 Chrome 탭 부분 녹화를 대안으로 비교함. 반복 재편집을 위한 전체 원본 확보도 선택 경로로 남길 수 있음.

구간 가져오기는 실제 시작 및 끝, 음성, 전송량과 사용자 대기를 검증함. 부분 녹화는 재생 시간, 버퍼링, 재생 UI와 음성에 영향을 받으며 지나간 장면은 재재생하거나 사전 버퍼가 있어야 함. 항상 녹화하는 과거 구간 버퍼는 초기 범위에 포함하지 않음.

획득 방식이 달라도 사용자에게 제공하는 구간 및 편집 결과의 의미는 같아야 함. 선택 방식이 실패하면 조용히 다른 방식으로 전환해 품질이나 대기를 숨기지 않고 상태와 다음 행동을 안내함.

## 5. UI 및 UX 기준

- 가볍고 쾌적하며 단순하지만 깔끔하고 예쁜 화면임.
- 시청 중에는 시작과 끝 표시만 드러냄. 원 영상을 큰 도구 모음으로 덮지 않음.
- 편집 화면은 미리보기, 구간과 구도 조절, 쇼츠 만들기에 집중함.
- 좁은 사이드 패널에 두 영상과 모든 옵션을 넣지 않음. 정밀 편집에는 별도 편집 탭을 사용할 수 있음.
- 화면 반응과 무거운 처리를 분리하고 구간 선택과 편집 상태를 불필요하게 잃지 않음.
- 미리보기와 출력은 같은 설정을 사용함. 표시 좌표를 원본 해상도로 환산해 결과 위치를 검사함.
- 출처 URL 및 원본 구간 시각을 작업 자료에 보존함. 영상의 출처 자막 삽입과 링크 복사는 선택 기능 후보임.
- AI 점수, 전체 라이브러리, 내부 실행파일이나 코덱 설정을 첫 화면에 두지 않음.

밝은 앱 배경과 어두운 영상 영역, 제한된 강조색과 충분한 여백은 시안 후보임. 이전 검토의 색상 및 Pretendard 선택은 사용자가 고정한 스타일이 아니며 구현 전에 핵심 상태 시안으로 확인함.

## 6. 초기 범위와 후속 목표

초기 Chrome 제품은 수동 구간 선택, 구간 확보, 트림 및 CROP/PAD, 음성을 유지한 MP4 저장, 진행 및 취소, 구간 원본 보존과 재편집을 포함함. 모바일은 최종 제품 목표이나 초기 Chrome 버전에 구현됐다고 표시하지 않음.

자막, 흐린 배경, 자동 추천, 자동 피사체 추적, 배치와 전역 라이브러리는 후속 후보임. 9월 문서의 v2/v3 범위는 새 구현 계획에서 재정리하고 이번 승인만으로 모든 후보를 필수화하지 않음.

## 7. 구현자가 결정할 사항

- Chrome 확장과 로컬 프로그램의 연결: Native Messaging 또는 안전하게 제한한 localhost 연결을 비교해 결정함. 설치, 기동, 포트, 오류와 취소까지의 계약을 기록함.
- UI 구현: 기존 Svelte/Vite 계획과 순수 확장 코드의 재사용성을 검토함. React 등 다른 프레임워크로 무단 대규모 전환하지 않음.
- Chrome의 content script, panel 및 편집 탭 역할과 폴더 구조를 정함. 임시 팝업이 닫힐 때 진행 작업이 끊기지 않게 설계함.
- 구간 자료형, 로컬 파일 시각과 원본 시각 매핑, 확보 파일의 보존 및 정리를 정의함.
- 부분 녹화 제공 시점은 실측 후 결정함. 더 빠르거나 더 가볍다고 미리 단정하지 않음.
- 모바일 출시 순서, 최소 OS, 구간 확보 및 네이티브 인코딩은 별도 계획으로 정의함. 모바일 완주 목표를 바꾸지 않음.

이 선택들은 승인된 목적 안의 구현 설계 항목임. 목적, 설치 부담의 중요한 확대, 클라우드 사용이나 모바일 목표 축소 등 사용자 결과를 바꾸는 선택은 합의가 필요함.

## 8. 첫 연결의 완료 조건

- 실제 Chrome YouTube 시청에서 시작과 끝을 지정하고 해당 영상의 구간이 확보됨.
- 표시 구간과 결과의 실제 장면 및 길이가 일치하고 음성이 유지됨.
- 화면 크기가 달라도 크롭 위치가 미리보기와 출력에서 일치함.
- 실제 프로세스 취소가 동작하고 인코딩 취소 시 구간 원본을 보존함.
- 최초 설치 및 연결 실패의 다음 행동이 명확하고 반복 실행에 불필요한 설정이 없음.
- 같은 확보 구간에서 재편집할 수 있고 새로고침과 영상 이동 시 작업 식별자를 혼동하지 않음.
- 구현, 단위 검증, 실제 영상 및 사용자 UX 확인을 구분해 보고함. skipped를 실물 관문 통과로 표시하지 않음.

이 조건의 성능과 품질은 아직 측정하지 않았으며 다음 세션의 검증 대상임.
