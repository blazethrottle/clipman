# clipman 설계 명세 (Design Spec)

- 작성일: 2026-09-01 (KST)
- 상태: 설계 확정안 (사용자 사인오프 대기)
- 벤치마크: cobalt.tools (동영상 다운로드 프록시, 오픈소스 AGPL, Node+Svelte)

## 확정된 근본 결정 (사용자 입력 기반)

| 결정 | 값 | 근거 |
|---|---|---|
| 배포 형태 | 개인용 로컬 도구 | 사용자 선택. 법적 리스크 최소, 가장 가벼운 시작 |
| 앱 형식 | 로컬 웹앱 (localhost 서버 + 브라우저 UI) + 파이썬 백엔드 | Web/App 비교 결과 A안. 편집 처리를 로컬 PC에서 수행해야 하는 조건이 순수 브라우저(C안)를 탈락시키고, 네이티브 앱(B안)은 v1 이후 승격 경로로 남김 |
| 편집 범위 | v1 최소(자르기+세로 변환), v2/v3 확장 로드맵 내장 | 사용자 선택. 아키텍처가 로드맵을 흡수하도록 설계 |
| 1순위 소스 | YouTube | 제품 목적. 추후 다중 플랫폼 확장 가능 |

## 1. 서비스 기획

### 1.1 제품 정의와 가치 제안

clipman은 긴 YouTube 영상에서 원하는 구간을 잘라 세로형 쇼츠 영상으로 만드는 개인용 로컬 도구다. 핵심 가치는 **"다운로드부터 쇼츠 완성까지 툴을 갈아타지 않고 한 흐름으로 처리한다"**는 통합성이다. 다운로드만 필요하면 cobalt 셀프호스팅으로 충분하고 편집만 필요하면 CapCut 같은 무료 도구가 있으므로, clipman의 존재 이유는 두 작업을 하나의 워크플로로 붙이는 데 있다.

### 1.2 타깃 사용자와 사용 시나리오

- 주 사용자: 본인 (비개발자, K-pop 및 팬덤 콘텐츠를 다룸)
- 대표 시나리오: 무대 영상, 인터뷰, 직캠 같은 긴 가로 영상에서 하이라이트 구간을 골라 세로 9:16 쇼츠로 만들어 SNS에 올린다
- 사용 빈도: 필요할 때 반복 사용 (상시 실행형 서비스가 아님)

### 1.3 핵심 기능 (v1 MVP)

1. URL 붙여넣기 후 영상 메타 조회 (제목, 길이, 썸네일, 사용 가능한 화질 목록)
2. 화질 선택 후 로컬 다운로드
3. 미리보기와 타임라인에서 구간 지정 (시작점과 끝점 = 자르기)
4. 세로 9:16 변환 (중앙 크롭 / 위치 조절 크롭 / 여백 채우기 중 선택)
5. 쇼츠 규격 mp4로 내보내기 후 결과 폴더 열기

### 1.4 비목표 (v1에서 하지 않을 것, YAGNI)

- 계정, 로그인, 클라우드 저장, 협업 기능
- 다중 플랫폼 (v1은 YouTube만)
- 자막과 자동 하이라이트 (v2, v3으로 미룸)
- 공개 배포와 호스팅 (로컬 전용)

### 1.5 로드맵 (사용자 필수 요구)

| 단계 | 범위 | 추가되는 핵심 기술 |
|---|---|---|
| v1 (최소) | 다운로드 + 자르기 + 세로 변환 | yt-dlp, ffmpeg |
| v2 (중간) | 자동 자막(음성인식) + 텍스트 오버레이/캡션 스타일 | whisper 계열 STT, ffmpeg 자막 렌더링 |
| v3 (풀) | 자동 하이라이트 구간 추천 + 배경음악/전환 효과 | 음성 에너지·장면 전환 분석 |
| 확장 후보 | 다중 플랫폼(TikTok, Instagram), 배치 처리, 사용자 프리셋 | yt-dlp 다중 추출기 |

아키텍처 원칙: v2, v3의 신규 기능은 기존 편집 엔진 옆에 **독립 모듈로 추가**되도록 설계한다. 즉 로드맵을 진행해도 v1 구조를 갈아엎지 않는다.

### 1.6 성공 지표 (개인 도구 기준)

개인 도구이므로 DAU 같은 지표 대신 실사용 효용을 측정한다.

- 1차 검증: URL 붙여넣기부터 쇼츠 mp4 내보내기까지 다른 툴로 이탈하지 않고 완결되는가 (통합 가치의 직접 검증)
- 유지 지표: 크래시 없이 반복 사용 가능한가, 다운로드 성공률이 유지되는가 (YouTube 변경에 yt-dlp 업데이트로 대응)
- 궁극 지표: 내가 실제로 계속 쓰는가, 기존 워크플로 대비 시간이 단축되는가

### 1.7 법적·윤리 가드레일

- YouTube 이용약관은 다운로드 기능 제공을 원칙적으로 금지한다. clipman은 개인 용도 및 본인이 권리를 가진 콘텐츠 사용을 원칙으로 하며, 공개 배포하지 않는다.
- 앱 내에 사용 책임 고지 1줄을 둔다.
- 로컬 전용이므로 저작권 및 DMCA 리스크 노출이 공개 서비스 대비 현저히 낮다.

## 2. UI/UX 기획

### 2.1 설계 원칙

- cobalt처럼 첫 화면은 극단적으로 단순하게 (입력창 하나)
- 편집은 필요할 때 펼쳐지는 단계로 노출 (한 번에 모든 컨트롤을 보여주지 않음)
- 비개발자가 봐도 3단계로 끝나는 명료한 흐름

### 2.2 화면 흐름 (3단계, 단일 페이지 내 전환)

1. 가져오기(Import): URL 입력 → 조회 → 영상 카드 확인 → 다운로드
2. 편집(Edit): 미리보기 + 타임라인 구간 지정 + 세로 변환 옵션
3. 내보내기(Export): 진행률 → 완료 → 결과 폴더 열기 또는 새 작업

### 2.3 와이어프레임

가져오기 화면:

|                                                            |
|     +--------------------------------------------------+   |

|                              [ 조회 ]                       |
|                                                            |
|   -- 조회 후 --                                            |
|   +----------+  제목: BTS 무대 직캠 4K                     |
|   | 썸네일    |  길이: 12:34                                |
|   +----------+  화질: [ 1080p v ]        [ 다운로드 ]       |

### 2.4 핵심 인터랙션

- 클립보드에 YouTube URL이 있으면 입력창 자동 채움 또는 원클릭 붙여넣기
- 타임라인: 좌우 핸들 드래그로 구간 지정 + 시:분:초 정밀 입력 병행
- 세로 크롭: 미리보기 위 9:16 프레임을 드래그로 이동해 핵심 인물이 프레임 안에 오도록 조정
- 처리 상태: 다운로드 단계와 인코딩 단계를 구분해 표시, 취소 가능

### 2.5 시각 방향

- 다크 테마 기본 (영상 편집 도구 관례, 미리보기 몰입)
- 큰 붙여넣기 필드, 미니멀 레이아웃, cobalt의 절제된 미학 참고

## 3. 프로덕트 아키텍처

### 3.1 개요 (로컬 3계층)

```
[브라우저 SPA]  <--HTTP/폴링-->  [로컬 파이썬 서버(FastAPI)]  -->  [미디어 엔진]
   화면/편집 UI                     API + 작업 관리                yt-dlp, ffmpeg
                                          |
                                   [로컬 저장소]
                                   원본/결과물/작업메타
```

전부 사용자 PC 안에서 동작한다. 브라우저는 화면만 담당하고, 무거운 처리(다운로드, 인코딩)는 로컬 파이썬 서버가 미디어 엔진을 호출해 수행한다.

### 3.2 컴포넌트 분해 (단일 책임, 독립 테스트 가능)

프론트엔드(`ui/`):
- 화면 컴포넌트 (가져오기, 편집, 내보내기)
- API 클라이언트 (백엔드 호출 래퍼)
- 로컬 UI 상태

백엔드(`api/`):
- 라우터: REST 엔드포인트 모음
- `downloader`: yt-dlp 래퍼 (메타 조회, 다운로드, 진행률)
- `editor`: ffmpeg 명령 생성기 (자르기, 9:16 변환, 내보내기)
- `jobs`: 작업 큐와 상태 (장시간 작업을 비동기로 실행, 진행률 폴링 제공, 취소)
- `files`: 저장 경로 관리, 결과 폴더 열기

실행기(`launcher`):
- 더블클릭 시 로컬 서버 기동 후 브라우저 자동 오픈 (Windows용 스크립트)

이 경계의 이유: 다운로드와 편집을 분리하면 각각 독립적으로 교체·테스트할 수 있다 (yt-dlp만 업데이트하거나 ffmpeg 옵션만 바꾸는 식). `jobs` 계층이 장시간 작업의 진행률과 취소를 한 곳에서 관리한다. 로드맵 확장(v2 음성인식 엔진, v3 하이라이트 분석)은 `editor`, `jobs` 옆에 새 모듈로 붙으므로 기존 구조가 바뀌지 않는다.

### 3.3 데이터 흐름 (URL → 쇼츠)

1. UI가 URL을 `POST /api/probe`로 전송 → `downloader`가 yt-dlp로 메타 반환 (제목, 길이, 화질 목록)
2. UI가 `POST /api/download {url, format}` → `jobs`가 다운로드 작업 생성 → UI는 `GET /api/jobs/{id}`로 진행률 폴링 → 완료 시 로컬 파일 경로 수신
3. UI가 편집 파라미터(시작, 끝, 크롭 방식)를 `POST /api/export`로 전송 → `editor`가 ffmpeg 명령 생성 → `jobs`가 인코딩 실행 → 결과 mp4 경로 반환
4. UI가 결과 폴더 열기 요청 → `files`가 OS 파일 탐색기로 폴더 표시

### 3.4 기술 스택 (확정 제안)

| 계층 | 선택 | 이유 |
|---|---|---|
| 백엔드 | Python 3.11+, FastAPI, uvicorn | 비동기 처리 간결, yt-dlp·whisper와 같은 언어라 로드맵 흡수 용이 |
| 다운로드 | yt-dlp (번들 실행파일, subprocess 호출) | 자체 추출기를 만들지 않고 검증된 도구 사용 (1루타 전략). 실행파일로 호출하면 취소(프로세스 종료)와 자체 업데이트(yt-dlp -U)가 쉽고 ffmpeg와 실행 모델이 통일됨 (상세는 개발 아키텍처 문서) |
| 미디어 처리 | ffmpeg (시스템 설치 또는 번들) | 자르기·크롭·스케일·인코딩의 사실상 표준 |
| 작업 상태 | 인메모리 딕셔너리 (+ 선택적 SQLite) | 단일 사용자 로컬 도구라 복잡한 큐 불필요 |
| 진행률 전달 | 폴링 (GET) | WebSocket보다 단순하고 견고. v1에 충분 |
| 프론트엔드 | Svelte + Vite | 벤치마크 cobalt와 동일, 번들 작음, 편집 UI의 드래그 상호작용을 간결하게 구현. React로 대체 가능 |

### 3.5 세로 9:16 변환 처리 방식 (ffmpeg)

세 가지 변환 방식을 ffmpeg 필터로 구현한다.

- 중앙 크롭: 가로 영상의 중앙에서 9:16 영역을 잘라내고 1080x1920으로 스케일 (`crop=ih*9/16:ih,scale=1080:1920`)
- 위치 조절 크롭: 크롭 영역의 가로 오프셋을 사용자가 지정 (핵심 인물 위치에 맞춤)
- 여백 채우기: 원본을 가로에 맞춰 축소한 뒤 위아래를 채움 (단색 또는 흐린 배경). 흐린 배경 방식은 쇼츠에서 널리 쓰이며 v1.1 후보

자르기(trim)는 ffmpeg의 시작 시간(`-ss`)과 구간 길이(`-t`)로 처리한다.

### 3.6 에러 처리

- yt-dlp 실패 (비공개·지역제한·포맷 없음·YouTube 변경): 사용자 친화 메시지와 함께 yt-dlp 업데이트 안내 표시
- ffmpeg 실패: 로그를 캡처해 원인(코덱, 디스크 공간 부족 등)을 표시
- 장시간 작업: 취소 가능하게 하고, 취소 시 부분 파일 정리
- 네트워크·디스크 오류: 명확한 오류 메시지와 재시도 경로 제공

### 3.7 테스트 전략

- `downloader`: yt-dlp 메타 파싱 단위 테스트(모킹), 실제 다운로드는 짧은 공개 영상으로 스모크 테스트
- `editor`: ffmpeg 명령 생성기 단위 테스트(입력 파라미터에서 기대 명령이 나오는지 검증), 실제 인코딩은 샘플 파일로 스모크(출력 해상도와 길이 확인)
- `jobs`: 작업 상태 전이 테스트
- API: 엔드포인트 통합 테스트

### 3.8 패키징과 실행

- v1: 파이썬 가상환경 + ffmpeg + yt-dlp + 더블클릭 실행 스크립트 (서버 기동 후 브라우저 자동 오픈)
- 향후 옵션: PyInstaller로 단일 실행파일화, 또는 동일 UI를 Tauri 껍데기에 넣어 네이티브 앱(B안)으로 승격

| 항목 | 확정 | 근거 |
|---|---|---|
| 프론트엔드 | Svelte + Vite | 벤치마크와 동일, 번들 최소, 편집 UI의 드래그 상호작용을 적은 코드로 구현. React 대비 학습·유지 부담 낮음 |
| ffmpeg 배포 | 번들 동봉 (정적 빌드 또는 imageio-ffmpeg) | 비개발자가 별도 설치 없이 더블클릭만으로 실행 가능해야 함. 배포 크기 증가는 감수 |
| 여백 채우기 방식 | v1은 단색 여백, 흐린 배경은 v1.1 | v1 범위를 최소로 유지 (YAGNI). 흐린 배경은 효과 좋으나 필수 아님 |
| yt-dlp 사용 | 개인·로컬 용도로 채택 | 개인 용도 전제에 부합. 공개 배포 시에만 재검토 필요 |

## 5. 재심 대상 전제 (외부 검증 필요)

- yt-dlp의 YouTube 호환성은 YouTube 측 변경에 따라 깨질 수 있다. 정기 업데이트 경로를 구현 단계에서 마련한다.
- 번들 ffmpeg의 라이선스 조항(정적 빌드의 GPL/LGPL 구분)은 배포 형태를 바꿀 때 확인이 필요하다. 로컬 개인 사용에서는 문제 소지가 낮다.
- 세로 크롭의 "핵심 인물 자동 추적"은 v1 비목표다. v1은 사용자가 직접 프레임을 이동한다.
